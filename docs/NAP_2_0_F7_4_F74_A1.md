## A1.1 — Causa y acción específicas en Outbox

`src/NAP.Presentation/GitOutboxGuidance.cs` añade una función pura y cerrada sobre estado/código ya disponibles, con motivo, acción recomendada y clase de intervención: revisión de configuración/permisos, acción explícita tras revisión, o revisión administrativa. No lee archivos, Git ni Outbox, no interpreta stderr y no decide permisos ni ejecuta reintentos.

| Causa/códigos | Presentación e intervención |
| --- | --- |
| `git_policy_changed`, `git_publication_blocked`, `git-authorization-required`, `git-disabled` | Si la configuración ya leída permite distinguirlo: revocación, revisión/AuthorizationId anterior o falta de AllowCommit. Sin datos suficientes, se conserva la descripción amplia; grant nuevo no reactiva la operación. |
| Committed sin diagnóstico y AllowCommit sin AllowPush | Explica que commit no concede push, AutoCommitBatch no publica automáticamente y toda publicación manual requiere permiso/confirmación propios. |
| `git_identity_missing`, `git_plan_stale`, remoto/upstream inválidos | Revisión de identidad efectiva, fotografía/configuración/refs y fingerprints, sin replanear el lote. |
| `git_remote_changed`, `git_not_synchronized` | Cambio o divergencia potencial; inspección y comparación de SHA/vínculos antes de revisión externa. |
| `git_receipt_invalid` | El código nativo se comparte entre recibo inconsistente y RequireNoPending. Se muestran ambas posibilidades, se dirige al recibo anterior y se exige revisión administrativa si hay incoherencia; no se inventa una causa más precisa. |
| Evidencia/ownership no acreditados, integridad de commit/índice/almacén, rollback o verificación remota insuficientes | Conservar evidencia y Completed; revisión administrativa, sin adoptar ni reconstruir desde carpetas. |
| Busy, operación Git en curso | Esperar, pausar/detener host y resolver Running antes de otra solicitud explícita. |
| Remoto inaccesible/rechazo/timeout o primeros retries | Revisar disponibilidad/autenticación/reglas; solo owner/autorización original pueden solicitar un retry confirmado por el motor. |
| `git_push_attempt_3`, `git_push_retry_3`, `git-push-retry-exhausted` | Presupuesto automático de escritura agotado; puede quedar comprobación nativa acotada. No se concede cuarto push automático. |
| `git_push_exhausted_verify_1..2` | Escritura agotada y reserva de comprobación; mostrar la fila no consume ni renueva reservas. |
| `git_push_exhausted_verify_3`, `git_verify_retry_3`, `git_verify_attempt_3` | Reservas automáticas de comprobación agotadas; receipt Pushed durable solo se concilia mediante vía local nativa. La UI no consulta ni amplía budgets. |
| Código desconocido, texto no fiable o Blocked sin causa | Mensaje fijo de revisión administrativa, sin incorporar el texto a motivo/acción ni sugerir acciones destructivas. |
| Pushed sin diagnóstico | Hecho durable histórico; no promete tip remoto actual ni nueva publicación. |

`GitManagementUiModels.cs` expone Reason/NextStep/Intervention. `GitManagementViewModel.ApplyOutbox` proyecta copias de las filas con la configuración que ya tenía cargada, sin consultas nuevas ni cambios de sus identificadores/estado/autorización. ## A1.2 — Identificación humana del repositorio

`GitRepositoryIdentity.Label` toma exclusivamente UniverseId y ProductionRoot efectivo del contexto seleccionado. Proyecta `Repositorio: <carpeta> · universo <id>`, omitiendo ancestros y unidad; nombres de hoja vacíos, excesivos o con caracteres no admitidos usan una etiqueta genérica. Sin contexto muestra repositorio no configurado. Es una función de texto sin acceso al filesystem.

`ShellGitManagement.GitRepositoryLabel` deriva esa etiqueta localmente del Context actual; `ShellViewModel` notifica el cambio junto con Context/UniverseLabel al cambiar universo. XAML sustituye la frase fija anterior por el binding nuevo. No se transmite raíz/nombre nuevo por IPC, no se muestra URL/credencial y no se permite una raíz Git independiente. El binding SHA y rama/upstream/remoto existentes permanecen visibles en su ubicación anterior.
