## Problema y cambio exclusivo

Antes, `git_push_retry_3` o `git_push_attempt_3` hacían devolver `git-push-retry-exhausted` antes de llamar al motor. Un SHA publicado exactamente por un operador externo después del tercer error no se reconocía automáticamente, aunque el remoto ya contuviera CommitSha. El hallazgo se identificó por revisión; no se atribuye una ejecución de reproducción previa al auditor.

`GitBatchPublicationPush.cs` separa ahora el agotamiento de las escrituras y el presupuesto de comprobaciones posteriores. Al agotar los tres intentos de escritura, la misma autorización original vigente permite **hasta tres turnos adicionales exclusivamente comprobatorios**, usando el `GitProductionService.PushBound(... verificationOnly: true)` existente. Esta ruta nunca puede emitir `Git.Push`. No hay cuarto intento automático de publicación.

Cada turno comprobatorio reserva antes de entrar al motor un diagnóstico durable `git_push_exhausted_verify_1`, `_2` o `_3`, en el mismo final autenticado del batch y sus intents. El código significa simultáneamente **tres intentos de escritura ya agotados** y **n comprobaciones reservadas**. `PushAttempts` conserva el valor tres para los tres códigos; ni reinicio ni error de red los convierten en permiso para publicar.

| Resultado de la comprobación nativa | Efecto |
| --- | --- |
| RemoteTip == CommitSha, receipt/plan/config/identidad/HEAD/índice y outputs verificados | AlreadyPushed nativo, receipt Pushed y batch/intents Pushed conjuntamente; cero comandos push nuevos |
| RemoteTip == BaseHead | Committed y `git-push-retry-exhausted`; la consulta consume su reserva, sin nuevo commit ni push |
| Remoto inaccesible, timeout o fallo transitorio sin evidencia suficiente | Committed y `git-push-retry-exhausted`; reserva ya durable, sin reset del presupuesto ni cuarto push |
| Tres comprobaciones ya reservadas | Ningún nuevo ls-remote automático; mismo estado y barrera hasta revisión/acción explícita |
| Busy antes de poder comprobar | Se conserva la gestión previa: detener turno y restituir solo su reserva, sin mutación remota |
| Receipt/config/binding/commit conflictivos | Se conserva Blocked y la revisión humana; no se adopta evidencia ambigua |

Una caída después de reservar una comprobación puede consumirla aunque el proceso no alcance la consulta. Así, reconstruir servicios no permite sondeo infinito cada cinco segundos. Si el SHA se publica externamente después de agotar también las tres comprobaciones, o una caída consume la última reserva, se necesita una acción explícita: no se promete detección automática indefinida. `RetryPublication` conserva su decisión humana y validación de autorización original; no se activa por una política nueva.

La validación original de autorización precede a esta ruta. Revoked/Disabled/Manual siguen deteniendo las operaciones automáticas; otra revisión/AuthorizationId no habilita un receipt Committed antiguo. La excepción puramente comprobatoria de un receipt Pushed ya durable conserva sus controles previos. No se modifica el motor nativo, `RequireNoPending`, ningún mutex/orden de locks, schema Outbox/SQLite, receipt, clave HMAC, permisos, UI, producción ni credenciales. Job/Queue Completed permanecen independientes de Git.
